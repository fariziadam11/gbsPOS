- Uses the same MCP servers across AI coding tools (Claude Code, opencode, Command Code): servers already configured in one tool (e.g., codebase-memory-mcp) should also be installed/registered in Command Code, and the user expects the assistant to check other tools' configs (opencode.json, .claude.json) to compare and align the setups. Confidence: 0.8

- Run the full test suite to verify completeness — Playwright against the dev server plus Vitest — rather than only building. Confidence: 0.8
- Frontend code must match backend response payloads exactly; check every endpoint's response shape to avoid silent data mismatches. Confidence: 0.8
- Communicates in Indonesian (Bahasa Indonesia), often mixed with English technical terms. Confidence: 0.95

Confidence: 0.7
- Answers to the user's short confirmatory questions (e.g., "berarti di payment-companion tidak ada warmup ya?", "tapi sudah seperti :app kan yang payment-companion?") should start with a clear yes/no verdict, backed by file-level evidence, and end with an offer to implement the fix; the user routinely double-checks that a module was aligned exactly as instructed before moving on. Confidence: 0.75
- When a feature in one module keeps failing, the user expects the implementation to be aligned with how an existing, known-working module in the same repo does the same feature (e.g., follow how the `:app` module runs SoftPOS payment) rather than keeping a divergent or speculative approach. On explicit instruction ("ikuti saja seperti :app"), the alignment should be exact: same call flow, same config (e.g., SoftPOS package name from manifest metadata `softposName` with fallback), and removal of speculative code the reference never uses (e.g., warmup calls) so the module behaves identically. The user also proactively proposes "kita harus seperti :app" as the desired UX target for payment flows, not only as a fix for failures. Confidence: 0.9
